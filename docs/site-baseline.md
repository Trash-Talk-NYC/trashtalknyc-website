# Site baseline and test checklist

This is the state of the site as of the 2026-11-24 production release (PRs #40–#47), and the checks every change should pass.
The captain asked for it (2026-11-25) so the current pages become the base we build on, instead of renovating them wholesale each round.
When a change moves the baseline, update this file in the same PR.

## Site-wide

- The header has the vest logo and "Trash Talk NYC", the Join button, the menu, and the EN/ES toggle. The toggle works in the page, so there is no `/es` route.
- The footer has the vest logo beside the socials (Instagram, TikTok, YouTube, Spotify, Facebook, LinkedIn), then a compact grid of links.
- Link previews use the 1200×630 share card: the vest logo, "New York City's Cleanup Club", and a sticker pile.
  It is generated by `node scripts/generate-icons.mjs`, and `og:image` carries a `?v=` version to bump whenever the card changes.
- The team's ten stickers are placed by spot ID in `src/lib/teamStickers.ts`. The homepage hero's sticker layout stays as it is.
- The Wall is parked behind `WALL_LIVE` in `src/lib/partners.ts`, so `/the-wall` is a 404 while its code stays in the repo.

## Club Events

- The upcoming list opens on "Upcoming". A tiny "Nearest first" label shows only once the list is sorted by distance.
- On phones each event is a ticket (E3): the title, date and time with a yellow distance pill, the venue, an "Address & maps" fold, a full-width Register button, and one corner sticker.
- On desktop each event is a wide ticket (D1): details on the left, Register on the right, and a strip of seven stickers along the top.
- After the list, the "Never miss a cleanup." banner carries the "Get them in your inbox" button.
- The "How to Start a Trash Club" guide link never splits across lines (it sits in a `.nowrap` span, here and on Contact).
- Past events are grouped by borough, and every borough starts folded.

## Contact

- The headline is "Let's talk trash together", with "together" plain (no highlight or hover).
- Picking a form tile scrolls to that form and focuses its first field.
- The General form has a "This is about a website problem or bug" checkbox, which sends the message to fabiola@ tagged `[Bug]`.
- The Partner form asks for the kind of partnership as "check all that apply", and each ticked kind adds its inboxes.

## Form email routing

These env vars are set in the production, branch-deploy, and deploy-preview contexts on Netlify. `docs/inbox-routing.md` has the full table.

- General → contact@ (`CONTACT_NOTIFY_TO`)
- Website problem or bug → fabiola@ (`BUG_NOTIFY_TO`)
- Brand Partner → partnerships@ (`SPONSOR_NOTIFY_TO`)
- Lead a Cleanup → events@ (`LEAD_NOTIFY_TO`)
- Partner, podcast → podcast@ and partnerships@ (`PODCAST_NOTIFY_TO`, `PARTNER_CONTENT_NOTIFY_TO`)
- Partner, content, influencer, or other → partnerships@ (`PARTNER_CONTENT_NOTIFY_TO`)
- Partner, nonprofit → partnerships@ (`NONPROFIT_NOTIFY_TO`)
- Partner, corporate event → partnerships@ and events@ (`PARTNER_CONTENT_NOTIFY_TO`, `LEAD_NOTIFY_TO`)
- A Partner or Brand Partner message that mentions "podcast" also copies podcast@.

Every form also adds the person to its Brevo list:

| List | Form | Env var |
|---|---|---|
| 9 | Newsletter signup | `BREVO_LIST_ID_SIGNUP` |
| 10 | General contact | `CONTACT_GENERAL` |
| 11 | Partner contact | `CONTACT_COLLAB` |
| 13 | Brand Partner contact | `CONTACT_SPONSOR` |
| 16 | Lead a Cleanup | `BREVO_LIST_ID_LEADS` |

## Test checklist for every change

- Check phones at 375, 390, and 430px and desktop at 1440px, in English and in Spanish. The `visual-qa` skill has the full breakpoint matrix.
- Make sure there is no sideways scroll and no sticker covers text or a button.
- Make sure every internal link loads and The Wall stays hidden.
- Send one test per form, then confirm in the Brevo transactional log that the right inbox got it.
  Production forms need a real person to pass the Turnstile check.
  Never test with a real person's email, because the submission overwrites that Brevo contact. Delete your test contacts afterward.
- Make sure the link preview shows the vest logo.

## Release routine

1. Open a PR with the change into `development`.
2. Check it on the dev site, https://development--trashtalknyc.netlify.app, and get the captain's OK.
3. Open one `development` → `main` release PR, which deploys https://trashtalknyc.org once merged.
4. Merge every PR into `development` and every release into `main` with **"Create a merge commit"**, never squash or rebase, so the two branches keep a shared history (see "Branches and releases" in `AGENTS.md`).
5. `main` requires a code-owner review before merging.
